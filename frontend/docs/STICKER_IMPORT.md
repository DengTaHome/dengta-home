# 私人表情架与 B 站 / 小红书灵感搜集

2026-10-17 本地实现。尚未部署，也没有发布新 APK。

## 怎么使用

设置 → 头像、背景与表情包 → 表情包架。

- 手动上传支持一次选择多张 JPG、PNG、WebP 和 GIF；GIF 与动画 WebP 保留帧间隔、循环次数和透明背景，可以搜索名称、描述和心情。
- “B站灵感搜集”可以粘贴 BV 号或完整 `https://www.bilibili.com/video/BV…` 链接，将视频静态封面保存到当前账号、当前伴侣的私人表情库。
- “允许伴侣自己搜集并发送表情”默认关闭，开启后 AI 可以先搜索再导入，每次回复最多附加一张。
- “小红书灵感搜集”先在当前账号和伴侣的独立登录会话中搜索，选择笔记后保存其封面；小红书自动搜集有单独的默认关闭开关。两种来源与已有表情合计每轮最多附一张，不会在小红书发帖或评论。
- 在表情卡片点“查看图片来源”可查看原视频与创作者。手动上传的图片可能没有外部来源。
- 搜集的是外部视频封面，不是现场绘画、原创图片或动画表情。只保存和分享有权使用的素材。

## 已知范围

自动搜集目前支持 B 站视频封面与小红书搜索卡片封面，保存 JPG、PNG、WebP，经既有私人媒体转换与大小限制处理。不会自动读取笔记图集或视频，也不从任意图片网址导入。B站短链接不会自动跳转；请粘贴 BV 号或完整视频链接。

小红书需先在设置中连接自己的登录态。搜索支持第一页默认排序；同一独立浏览上下文保留最近100条来源、有效10分钟，连续搜索不会立即丢弃先前结果。超过期限、上下文被回收、服务重启或重新登录后，首次导入需重新搜索。已保存的导入回执可在重试时复用，完成入库不依赖旧搜索缓存继续存在。搜索列表先显示标题与作者，保存后的图片显示在私人表情架中。

## 动态表情

单张上传及转换结果均不能超过 12MB；动画最多 240 帧，解码累计像素最多 4000 万，每帧仍执行原有表情图片像素限制，输出缩放到 768×768 内。超过限制时明确提示缩小尺寸或减少帧数，不会悄悄截去后半段或转成静态表情。

保存时重编码为 WebP，去除 EXIF 等原图元数据，继续使用已有私人存储与表结构，不需要为动图新增数据库迁移。头像和聊天背景仍按原有静态格式校验。

聊天和表情架中的动图可暂停、恢复，暂停显示第一帧；滑出屏幕或页面退到后台时移除播放图像，首次可见后才读取原图。暂停预览按需从同一鉴权接口生成，不新增存储对象，仍受账号和伴侣权限约束。恢复播放从头开始，不提供逐帧定位。

开启系统“减少动态效果”后默认显示静态预览，用户可明确选择播放。当前为判断 WebP 是否包含动画，首次可见仍需下载原文件；不会先显示动画。离屏期间保留当前组件私有的 Blob，避免来回滑动重新下载，卸载或切账号/伴侣时销毁；没有跨账号公共缓存。

公开搜索不携带私人 Cookie；详情读取只使用当前账号与伴侣保存的 B 站登录态。图片 CDN 请求不发送登录 Cookie。平台风控、视频下架或登录失效仍可能导致外部访问失败。

上句公开搜索指 B 站；小红书使用当前账号与伴侣的独立已登录浏览上下文。两种来源的图片 CDN 下载均不携带 Cookie 或服务令牌，限定官方图片主机、固定 DNS 解析、禁止重定向并限制完整读取时间。外部登录过期使用 `cookie_expired` / HTTP 409，不会注销灯塔账号；灯塔自身登录失效仍为 401。

AI 搜集当前接在有持久化请求编号的主聊天链路。语音单独入口等没有持久化请求编号的入口保留原有表情选择功能，不开放自动导入。

## 重试和账号保护

导入编号按账号与伴侣保存；同一次视频导入在断网、重开面板或刷新网页后复用原编号。重复点击不会并发提交；失败后需要用户主动重试，不自动重传。

服务端先保存导入回执与计划图片编号，再下载并写入私人存储。同一请求跨服务实例并发时保留一张图片，清理失败实例自己的存储对象。已完成导入的图片被删除或归档后，原请求不会重新创建。

前端对鉴权、响应读取及 JSON 处理设置完整的 45 秒截止时间。切换账号、切换伴侣、关闭面板后取消操作并忽略迟到回执；迟到的鉴权回调也不能更改登录态。

在存储服务中途故障且数据库回执仍为 pending 的极端情况下，需要先在原账号核对结果。跨进程测试使用 PGlite 与两个独立服务实例，不能替代生产数据库网络故障验收。

## 数据库与上线

后端本地草稿：`backend/supabase/drafts/bilibili_sticker_import.sql`。

小红书扩展草稿：`backend/supabase/drafts/xhs_sticker_import.sql`，应在上一个草稿之后生成正式迁移、经授权应用。新增默认关闭的 `xhs_enabled`，扩展来源类型与资源编号联合约束；不修改已有 B 站偏好、账号和伴侣复合外键、回执唯一性、RLS 与后台专用权限。本地 PGlite 已验证按顺序重复执行和原有用户字段不变，生产未应用。

草稿增加偏好与导入回执两张表，不改已有个性化指令、记忆、消息或图片。使用 RLS，撤销 `anon` 与 `authenticated` 的直接访问，仅后端 `service_role` 可访问；后端查询仍强制限定账号与伴侣。

缺少表时功能显示待更新并保持关闭，现有手动上传和发图继续使用。正式上线前需要用 Supabase CLI 生成正式迁移，经授权后应用，再部署前后端和验收真实账号。当前未执行这些外部写操作。

## 验证

前端：`npm run test:private-media`；后端：同名脚本（包含 `test:animated-stickers`）。覆盖真实本地 HTTP 路由、GIF/动画 WebP 解码、实际帧数据与时间、私人保存、静态预览、SQL 重复执行、回执重放、重复提交、撤销授权、账号与伴侣隔离、超时、迟到响应及设置组件交互。数据库为本地 PGlite，图片与账号均为虚构测试样例。组件测试不能替代浏览器动效和手机帧率验收。

round37 另运行前后端 `npm run test:xhs`，含真实请求层验证：外部小红书失效不会触发灯塔退出，而灯塔自身失效仍触发认证恢复。浏览器证据 `docs/release-evidence` 覆盖界面、独立网页 worker、来源、PGlite 回执、WebP 保存、私有图片读取和重复导入。真实小红书账号、CDN 和模型自主调用仍未验收。

### 独立仓库与集成测试

当前 `npm run test:xhs` 只运行前端单元/组件测试，可在独立前端仓库执行，不要求后端源码。发布检查还必须显式执行 `npm run test:xhs-integration`，验证实际前端请求层 → 后端私人媒体路由 → 本地 PGlite fixture，确认外部登录过期不会注销灯塔；这项不能由纯前端检查替代。

先在前后端目录分别运行 `npm ci`。集成测试默认支持两个相邻布局：公开合并仓库的 `frontend/` + `backend/`，以及独立仓库的 `dengta-home-frontend/` + `dengta-home-backend/`。其他目录可以设置 `DENGTA_BACKEND_TEST_ROOT` 为后端根目录（相对路径按命令当前目录解析），再在前端执行集成脚本。该变量只用于本地测试，不是 API 地址或凭据，无需生产环境配置。

后端不存在或缺少 fixture 时，集成脚本明确失败并输出准备步骤，不会静默 skip。CI 必须为集成任务准备两端源码及依赖；独立前端默认全量测试仍可单独运行。测试只使用虚构账号和本地数据，不要求生产密钥或真实小红书登录。
