# 安卓更新提醒与发布

应用打开和返回前台时检查公开版本清单，成功结果最多缓存一小时；设置里的“检查应用更新”立即重新检查。新版本弹窗显示版本、大小、更新内容，由用户选择“稍后提醒”或“下载更新”。同一版本稍后提醒有效一天，新版本不受旧提醒影响。正在聊天、输入、使用其他弹层时，自动弹窗等待空闲显示。

安卓 WorkManager 独立检查公开版本，约 30 分钟或更久，受网络、电量和系统限制，不能承诺即时推送。它不依赖伴侣推送凭据，不发送账号、聊天和定位。设置内“更新提醒设置”可关闭后台任务；系统通知权限仍由用户控制。用户点击系统更新通知会重新读取清单，不能直接信任通知内的下载链接。

更新清单为 `https://www.dengtahome.com/updates/android.json`。只允许本项目 GitHub Release 的 HTTPS APK，必须有版本号、递增 build、SHA-256、文件大小、日期及更新说明。清单请求不带账号令牌或 Cookie，拒绝重定向、HTML 和超过 64 KiB 的响应。清单不可用不会影响聊天。

前台检查与后台通知均拒绝字符串、小数或超出安卓整数范围的候选 build，并要求完整的发布元数据；通知通道被系统关闭时，不会把本轮标记为“已经通知”。通知开关保存期间会禁用重复操作，启动时较晚返回的设置读取不会覆盖用户刚保存的选择。

发布前清单的 `latest` 应为 null，表示尚未发布本轮 APK。不应填入尚未上传的下载地址；实际发布状态以部署后的清单为准。

本地 `vercel.json` 只对 `/updates/android.json` 开放不带凭据的跨域读取，并设置 `Cache-Control: no-store, max-age=0`，让 APK 的本地页面可以获取公开版本。该配置随网站部署后才生效；本地 Node HTTP 测试不能代替部署后的响应头与安卓 WebView 验收。

## 最后发布时操作

1. 完成待办与验收后再构建 APK，使用原有签名和相同包名；不要要求用户卸载旧版。
2. 在取得发布授权并确认发布目标后上传 APK 到 GitHub Release，先验证公开下载可达。
3. 准备 JSON 数组格式的更新说明，例如 `["修复返回手势", "改进后端重连"]`，运行以下脚本生成待审查的本地清单。脚本仅读取已有 APK，不构建、不上传，不覆盖现有清单；会用 aapt 和 apksigner 检查真实包名、版本、签名并计算摘要。

```powershell
node frontend/scripts\prepare-app-update.mjs --apk path/DengTa.apk --notes path/release-notes.json --url https://github.com/DengTaHome/dengta-home/releases/download/vX.Y.Z/DengTa-X.Y.Z-N.apk --output path/android-update-reviewed.json --sdk workspace/DengTa-production-tools\android-sdk
```

4. 审查清单并确认 APK 链接、签名、版本和更新内容，随后在发布授权范围内将该清单部署到网站的 `/updates/android.json`，配置不长期缓存该文件。
5. 用旧版真机验证：前台检查、后台通知、稍后提醒、通知入口、下载及系统覆盖安装，核对聊天、附件、账号和签名均保留。
6. 撤回有问题的新版本时，将清单改为 `latest: null` 或上一稳定版本。应用不会主动降级或强制安装。

离线、后台限制或通知被禁用时，用户可以打开灯塔手动检查。这个机制为公开清单检查及本地通知，并不是依赖推送厂商的即时远程推送。

## 已安装用户与下载边界

只有已经内置 AppUpdateCenter / AppUpdates 原生插件的 APK，才能自动读取上述清单或执行后台任务。旧 APK 若没有这些代码，部署网页、后端或更新 JSON 无法给它补出远程更新能力；这类用户需要先通过公开下载链接手动覆盖安装一次，后续版本才可以使用应用内提醒。是否具备能力应检查对应已发布 APK 的内置网页资源和原生插件，不能根据当前源码倒推所有旧版本。

“下载更新”目前打开系统浏览器，再由系统下载器和安装器处理 APK。应用本身不自动下载、不静默安装、不管理下载进度或取消；用户可在浏览器/系统下载页取消。清单中的 SHA-256 由发布准备脚本从真实 APK 计算，当前应用没有在下载后逐字节复验这个摘要，不能把清单校验称作 APK 下载校验。Android 覆盖安装会检查包名、签名与版本约束；发布时仍必须核对实际 APK 和下载内容一致，并保留相同签名，不要求用户卸载旧版。
