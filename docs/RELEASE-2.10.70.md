# DengTa Home 2.10.70 · Android 与播放器修补

本次更新仅修改前端、Android 构建版本及发行文档。后端源码和生产服务没有在本次发布中更新。

## 修改

- 将 Capacitor Android、Core、CLI 固定为 8.4.3，重新编译安装包，修复内部代理路径的 WebView 同源权限漏洞。[维护方公告](https://github.com/ionic-team/capacitor/security/advisories/GHSA-rvm3-566m-v7fv)。这是原生导航与权限修补，不改变聊天内容或提示词。
- 移除未使用的旧资源构建工具，直接声明实际使用的 Sharp，更新兼容范围内的依赖补丁；既有 23 项图标输出保持。
- 恢复播放超时或取消后保持暂停，阻止迟到的播放事件重新启动声音；明确发起的新重试仍可正常播放。
- 恢复、切歌和初次播放超时分别说明当前状态与重试入口。切歌失败保留当前歌曲。

## 本地验证

前端完整测试、lint、typecheck、网页构建和 Android 构建均退出 0。播放器逻辑与实际 React 组件回归共 26/26，通过受控 Audio 替身验证迟到事件、暂停和重试。

Android 单元测试 47 项、15 套测试结果零失败。安装包内 104 项网页资产与构建产物逐字节匹配；实际 DEX 中 7 项 Capacitor 导航守卫检查通过。另从已安装上游源码提取 3 个方法，以 Java 框架替身运行 44 个断言。后两项是静态与替身验证，不能代替真机 WebView、音频或投屏验收。

本次前端完整和生产依赖 audit 都为 0 项已知受影响节点。公开后端仍是上一版快照，新鲜 audit 为 1 critical、3 moderate：proxy-addr 仍为 2.0.7；其 2.0.8 修复已在开发工作树验证，但后端推送暂缓，本次未发布该修复。当前代理配置不使用公告涉及的子网编译路径，不能据此认为依赖漏洞已消失。其余 3 项来自 Mammoth → argparse → sprintf-js，同一依赖链尚无兼容补丁。后端自行部署前应单独审查并修补依赖，不应把前端 audit 结果当作全项目安全证明。
